## 0. 设计动机（一切取舍以此为准）

主创小时候的书桌**很脏很乱，什么都找不到**。这一关的迷宫不是“一个迷宫摆在桌上”，而是**一张乱到变成迷宫的书桌**：
- 墙就是一堆堆随手放的课本、文具、零食袋和杂物；
- 地面是压在一起的作业本和试卷；
- 缺口是旧书桌桌面裂开的缝、缺掉的木板。

玩家点亮台灯时，看到的应该是：**“天哪，这桌子乱成这样”**，而不是“一个整齐的网格迷宫”。

这一站对应**少年**时期。物品题材是少年时代用过、后来没再珍惜的东西：
- 课本、试卷、练习册；
- 游戏杂志、掌机、卡带；
- 耳机线、随身听、磁带；
- 奖状、同学录、没拆的生日卡；
- 零食包装、汽水罐。

**分寸：乱，但读得懂。**俯视角下必须一眼分清三件事：
1. 哪里能走；
2. 哪里是墙；
3. 哪里是缺口。

乱只体现在：
- 物件种类多、朝向歪、互相压叠；
- 地面上铺着纸。

**乱不能**把路口遮住，也不能让缺口看起来像能走。

## 1. 现有结构（不许改的部分）

`DeskMaze` 在 `_ready()` 里按种子生成，顺序是：
1. `_carve`
2. `_solve`
3. `_place_eraser_hole`
4. `_choose_item_cells`
5. `_place_holes`
6. `_build_floor_and_walls`
7. `_place_items`

| 量 | 值 |
|---|---|
| 网格 | 6 列 × 12 行 |
| 单格 | **0.1167 m × 0.1167 m**（桌面 0.70 × 1.40 m） |
| 桌面高度 | `top = 0.75` m |
| 引擎比例 | 1 m = 9 单位（`K = 9`） |
| 墙（碰撞） | 厚 `WALL_T = 0.015` m，高 0.03–0.06 m，放在每条“关闭的内部格边”上 |
| 净通道宽 | ≈ 0.10 m |
| 地面（碰撞） | 每个非缺口格一块 3 cm 厚的板 |
| 缺口 | 该格没有地板，掉下去就回到最近的检查点 |
| 桌面外缘 | 没有墙，掉下去同样回到检查点 |
| 镜头 | 俯视 −80°，屏幕上书桌横放，D 键向右朝门走 |

**硬约束：**
1. **碰撞完全不变**：地板块、墙块、橡皮、HoleFill、光源和检查点的位置和尺寸都不动。外观只是“挂”在上面。自动测试就是靠这些碰撞跑通的。
2. **同一个种子，迷宫布局必须和现在完全一样。**
   - 装饰随机要用**另一个独立的** `RandomNumberGenerator`，种子取 `used_seed * 7919 + 1`。
   - 绝不能从 `rng` 里多取数。否则所有已验证的种子都会失效。
3. **装饰不能泄露答案。**杂物的密度和种类必须与“是不是主路线”无关：
   - 不能读 `path` 来决定摆什么；
   - 只能读 `open`、`holes`，以及关键物的格子（用来避让）。
4. 公开 API 保持不变：`cell_world()`、`route_points()`、`path`、`holes`、`lights`、`eraser_index`、`hole_fill`、`note`、`used_seed`。

## 2. 代码方案

### 2.1 新文件 `scripts/desk_maze_dressing.gd`（`class_name DeskMazeDressing`）

- `DeskMaze` 在 `_place_items()` 之后调用 `DeskMazeDressing.new().dress(self)`。
- 也可以用 `@export var dressed := true` 来开关。关掉时就是现在的彩色方块，方便对比和排错。
- 新增 class_name 后要先跑一次 `godot --headless --path . --import`，否则会报类找不到。

`DeskMaze` 需要多暴露一点数据。只做记录，不改生成逻辑：
- `walls: Array`：每条墙 `[cell: Vector2i, dir: Vector2i, height_m: float, body: StaticBody3D]`，在 `_build_floor_and_walls` 里 append。
- `_tiles` 改成公开的 `tiles`，或者加一个 getter。
- 开启装饰时，把墙块和地板块的 `MeshInstance3D` 设为 `visible = false`，**StaticBody 和 CollisionShape 保留**。

### 2.2 摆放算法（按层）

**A. 墙段 → 杂物条**
1. 把同一条网格线上**连续的**关闭边合并成一段（run），长度为 L 格。
2. 用长度 1、2、3 格的“墙件”把这段填满：贪心加随机，优先用长件，剩下的用短件补。
3. 每个墙件的处理：
   - 偏航抖动 ±6°；
   - 沿墙方向错位 ±1 cm；
   - 30% 概率在上面再叠一件“叠放件”（见美术清单 B 组），叠放件随机旋转 0–360°。
4. 外观可以超出碰撞墙的厚度，但**每侧最多伸进通道 1.2 cm**（净通道 10 cm，小机器人要过得去，而且看起来要能过）。
5. 高度：外观顶面 ≥ 碰撞顶面。上限是格宽的 1.2 倍，约 14 cm，避免挡住俯视镜头。

**B. 网格交点 → 立柱件**
- 放在内部格点上，凡是有 ≥ 2 条墙在这里相交（拐角、T 口、十字）就放。
- 物件用：笔筒、胶带卷、马克杯、汽水罐、一摞便利贴、闹钟。
- 每个立柱件用来遮住墙件之间的接缝。占地直径 ≤ 3 cm，不能伸进通道。
- 有 20% 的交点放高件，高 8–14 cm。高件会在点灯时投下长影子，这是想要的戏剧效果。

**C. 地面层 → 纸张**
- 在非缺口格上随机铺纸，覆盖约 50% 的格子：试卷、作业本（打开或合上）、草稿纸、漫画书页、成绩单。
- 每张随机旋转。纸张可以跨格，也可以压到墙下，制造“压在一起”的感觉。
- **纸张不能盖住缺口。**它在缺口格上方最多伸出 2 cm（像撕破的纸边垂进黑洞），超出部分裁掉，或者换一张更小的纸。
- 厚度 ≤ 3 mm，无碰撞，`cast_shadow = OFF`。
- 地板本体换成旧木纹桌面材质。木纹方向沿桌子长边。

**D. 缺口 → 破桌面**
- 缺口格的四条边放“裂缝边”装饰：断掉的木板茬、翘起的木刺。外观不能伸进缺口超过 1 cm。
- 缺口下方 5 cm 放一块纯黑、不受光的面片，确保俯视时一眼就是“洞”。
- 现有的 `abyss` 材质可以参考。

**E. 散落层 → 小杂物**
- 用 `MultiMeshInstance3D` 撒小东西，每种一个 MultiMesh：
  - 铅笔屑、橡皮屑、回形针、图钉、断铅笔头、瓶盖、纸团、贴纸、糖纸；
  - 每格 0–4 个，全部无碰撞，`cast_shadow = OFF`。
- 不能撒在关键物格子（见 F）半径 3 cm 以内，也不能撒在缺口格里。

**F. 关键物 → 专属模型**（替换现在的彩色方块标记）

| 生成器里的东西 | 换成 | 备注 |
|---|---|---|
| `kind = "flashlight"`（起点） | 玩具手电筒，横躺，灯头朝终点方向 | 朝向用 `target_offset` 算 |
| `kind = "far"` | 夹式小台灯 / 书夹灯，灯头朝 `target_offset` | |
| `kind = "local"` | 掌机屏幕 / 电子闹钟背光 | 光从自身发出；掌机呼应下一关电视 |
| `kind = "lamp"`（死胡同里） | 旧的迷你台灯，这一关最“像宝物”的东西 | 最显眼 |
| 橡皮 `eraser`（9.5 cm 方块） | 一块用了很久的大号橡皮，被铅笔戳满了洞 | 外观严格 9.5 cm 立方，挂在 Pushable 下面 |
| 妈妈的纸条 `note` | 折过的便条，一半压在一张试卷下面 | 靠近时现有的发光逻辑照常生效 |

- 关键物所在格子里**不放 A/B 组的高件**，只允许纸张。
- 避让半径：以格心为圆心 4 cm 内只能有纸张。
- **配色禁令**（全游戏规则）：普通杂物**避免高饱和青色**，青色只属于主角和“可互动的东西”。
  - 四类光源、橡皮、纸条这些可互动物，可以有一点青色描边或青色小部件来提示。
  - 不能整件都是青色。

### 2.3 物件注册表（占位优先）

美术资源会陆续到，代码不要等美术：
- 新建 `scripts/desk_maze_kit.gd`（或者一个 `.tres`），每个条目包含：
  `id, group(A1/A2/A3/A_stack/B/B_tall/C/D/E/F_*), glb_path, size_m(Vector3), weight`
- 对应的 `glb` 不存在时，自动用**同尺寸、不同颜色的占位方块**代替。
- 这样先把整套摆放跑通，模型到一个替换一个。

### 2.4 种子池

- `DeskMaze` 新增 `@export var seed_pool: PackedInt32Array = []`。
- 选种子的顺序：
  1. `--maze-seed=N` 优先；
  2. 否则如果 `seed_pool` 非空，从池子里随机选一个；
  3. 否则沿用现在的完全随机。
- 新增 `tools/maze_seeds.gd`，作为 SceneTree 脚本，用 `godot --path . --script` 运行：
  1. 批量实例化 `DeskMaze`，种子 0–499，只生成不渲染，输出 `shots/maze_seeds/stats.csv`。
     - 列：`seed, path_len, holes, dead_ends, turns_on_path, has_eraser, has_lamp, note_on_path`。
     - 其中 `note_on_path` 表示纸条格在主路线上，也就是没找到死胡同的退化情况。
  2. 用下面的条件筛候选：
     - `22 ≤ path_len ≤ 30`
     - `10 ≤ holes ≤ 18`
     - `turns_on_path ≥ 10`
     - `has_eraser`、`has_lamp` 都成立
     - `not note_on_path`
  3. 对候选（最多 24 个）**带渲染**拍俯视截图，存成 `shots/maze_seeds/seed_N.png`。截图开全局光，便于看清结构。
  4. 拼一张 `contact_sheet.png`，每张标上种子号和统计数据。
- 交付给主创挑选。主创选出 3–5 个之后，写进 `room.tscn` 里 DeskMaze 节点的 `seed_pool`。
  - 这个节点是 `tools/gen_room.py` 生成的，所以**要改 gen_room.py**，不要手改 tscn。

### 2.5 性能

- 预算：
  - 墙件和立柱件实例 ≤ 250；
  - 纸张 ≤ 60；
  - 散落物走 MultiMesh。
- 投影：只有 A/B/F 组投影；C/E 组不投影。
- 整关进入俯视后，帧率在开发机上不能比现在低 10% 以上。用 `Performance.get_monitor(TIME_FPS)` 记一次放进自测输出。

## 3. 美术清单（给模型制作）

- 规格沿用 `art_audio_brief_bedroom_toybox.md` 第 2、3 节：
  - 风格化微缩、手绘贴图、不烤光影；
  - glb、Y 轴向上；
  - 真实米制尺寸；
  - 小道具 500–3,000 三角面，贴图 512。
- **额外要求：**
  - **原点放在底面中心。**
  - 墙件的**长度严格等于 1 / 2 / 3 格**，误差 ±5 mm：1 格 = 11.7 cm，2 格 = 23.3 cm，3 格 = 35.0 cm。
  - 长度方向沿 +X，厚度方向（Z）≤ 3.5 cm。
- **俯视为主**：镜头几乎垂直向下，**顶面是最重要的一面**。
  - 书的封面、试卷上的字迹、杂志封面都要画在顶面。
  - 侧面可以简单。
- 命名：`prop_desk_<名字>.glb`，放进 `inbox/`。
  - 先过 `tools/slim_glb.py`，再过 `tools/inbox.py check`，不能有 FAIL。

## 4. 验收（必须实际运行，不许跳过，不许编造结果）

1. **布局一致性**：对种子 7、123、4242，分别在 `dressed=false` 和 `dressed=true` 下打印 `path` 和 `holes`，两次必须完全相同。
2. **自动测试**：对种子 7、123、4242，以及种子池里的每个种子，运行：
   ```
   D:\Godot_v4.7.2-stable_win64_console.exe --path . res://scenes/room.tscn -- --autotest --shots=shots/dress_<seed> --maze-seed=<seed>
   ```
   输出里 `stop2` 的所有布尔项都必须为 true，并且 `route_respawns = 0`。原有第 0、1 站的检查也不能退化。
3. **截图**：每个种子提交三张，`room_s2_dark.png`、`room_s2_flashlight.png`、`room_s2_goal.png`。人工确认四点：
   - 缺口一眼可辨；
   - 通道没有被杂物遮住；
   - 关键物清楚；
   - 整体是“乱糟糟的书桌”。
4. **答案不泄露**：随机抽 3 个种子，开全局光截一张俯视图，确认从杂物密度上看不出主路线。
5. **导出**：用 `Windows Desktop` 预设导出到 `build/win/JamTest.exe`。**导出后核对 exe 的修改时间晚于导出开始的时间**，以前出过“导出失败、打开了旧版”的事故。
6. 写一份简短报告，放在 `docs/desk_maze_dressing_report.md`：
   - 每个种子的测试结果和截图路径；
   - 帧率前后对比；
   - 哪些模型是真模型、哪些还是占位块；
   - 没有测的项目明确写“未测”。

## 5. 建议顺序

1. 种子批量工具（2.4），先产出 `contact_sheet.png` 给主创挑种子。这一步和美术并行。
2. 装饰代码加占位块（2.1–2.3），跑通第 4 节的验收 1–4。
3. 美术按 ★ 优先出模型，入库后逐个替换占位块。
4. 非 ★ 物件、彩蛋纸张、细节打磨。
